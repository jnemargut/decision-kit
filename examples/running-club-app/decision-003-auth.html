How Do People Get In?

Twelve people who already know each other in real life. This decides how much friction sits between finishing a run and logging it.

Chosen
Option A
Magic link
Type your email, click the link, you are in
// one table, one email, no password to leak export async function signIn(email) { const token = crypto.randomUUID() await db.insert(loginTokens).values({ email, token, expiresAt: minutesFromNow(15) }) await sendEmail(email, `/auth/${token}`) }
+No passwords to store, reset, or leak
+Works with a thumb and no memory
−Depends on an email provider actually delivering
−Link-in-email is slow when you are standing outside sweating
Option B
Sign in with Strava
Borrow the identity they already use for running
// Strava already knows their runs const handler = NextAuth({ providers: [ Strava({ clientId: env.STRAVA_ID, clientSecret: env.STRAVA_SECRET, authorization: { params: { scope: "activity:read" } } }) ] })
+One tap, and it is the account they already associate with running
+Opens the door to importing runs automatically later
−Anyone without Strava is locked out of a twelve person club
−You inherit their rate limits and their outages
Option C
One shared club code
No accounts at all. Know the code, log a run.
// the entire auth system export function checkClubCode(input) { return timingSafeEqual(input, env.CLUB_CODE) } // the runner picks a name and we believe them. // it is a running club, not a bank.
+Nothing to build, reset, or breach
+Zero friction, which is most of the point
−Anyone with the code can log a run as anyone
−Removing one person means changing it for everyone
