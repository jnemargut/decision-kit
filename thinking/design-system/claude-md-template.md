## 1. Framework Adaptation

Detect the project's stack and adopt tokens accordingly.

**Detection order:**

1. **Tailwind** — `tailwind.config.{ts,js}` exists → extend `theme.colors`, `theme.fontFamily`, `theme.spacing`, `theme.borderRadius` from `tokens.json`. Do not overwrite existing Tailwind defaults — merge. Generate the config extension once, then write token references (e.g., `bg-brand`, `text-neutral-900`) in components.

2. **styled-components / Emotion** — `package.json` contains `styled-components` or `@emotion/styled` → create `src/theme.ts` (or `.js`) exporting a theme object shaped from `tokens.json`. Wrap the app in `<ThemeProvider theme={theme}>`. Reference tokens via `props.theme.colors.brand`.

3. **Svelte** — `svelte.config.{js,ts}` exists → import `tokens.css` in the root `+layout.svelte` or `app.html`. Reference tokens via `var(--color-brand)` in `<style>` blocks.

4. **Vue** — `vue.config.{js,ts}` or `vite.config` with `@vitejs/plugin-vue` → import `tokens.css` in the root entry. Reference via `var(--color-brand)`.

5. **CSS Modules** — `*.module.css` files present → import `tokens.css` globally (in `_app.tsx` / `main.ts` / root entry). Reference via `var(--color-brand)` inside modules.

6. **SCSS** — `*.scss` present → generate `_tokens.scss` from `tokens.json` (`$color-brand: #...`), import at the top of the main SCSS file.

7. **Plain CSS / nothing matched** — import `tokens.css` at the root (via `<link>` in HTML or `@import` in a global stylesheet). Reference via `var(--color-brand)`.

**When adapting:** never invent new color names, font sizes, spacing values, or radii outside what's in `tokens.json`. If a component genuinely needs a value not in tokens, flag it to the user rather than adding it silently.

## 2. Using Icons

Icons live in `design/icons/` as individual SVG files:

```
[LIST_OF_ICON_FILENAMES]
```

Each was generated specifically to match this system's stroke, corner radius, and terminal treatment.

**Do NOT swap in external icon libraries** (Lucide, Phosphor, Heroicons, Feather, etc.). They won't match the stroke weight or visual DNA — users will feel the mismatch immediately.

**For small icon sets — inline import:**

```tsx
import HomeIcon from '../design/icons/home.svg';
import SearchIcon from '../design/icons/search.svg';
// Use <HomeIcon className="..." /> or <img src={HomeIcon} />
```

**For larger icon sets — SVG sprite:**

1. Concatenate all `design/icons/*.svg` into a single `icons-sprite.svg` with each icon as a `<symbol id="icon-[name]">`.
2. Include the sprite once per page: `<svg style="display: none;"><use href="/icons-sprite.svg" /></svg>`.
3. Reference: `<svg><use href="#icon-home" /></svg>`.

Icon color inherits from `currentColor` — set on the parent: `color: var(--color-neutral-700)`.

**If the user asks for an icon not in the set:** Generate a new SVG that matches the existing set's stroke weight ([STROKE_WEIGHT]), corner radius ([RADIUS]), and terminal style ([TERMINAL]). Follow the anchor icon (`home.svg`) as visual reference. Save to `design/icons/`.

## 3. Using Typography

The typography pairing was curated specifically for this brand using the workshop's discovery signals. Two real Google Fonts: one for display, one for body. Don't substitute them — the pairing is the design.

- **Display font:** `[DISPLAY_FONT_FAMILY]` — for headlines, brand name, hero copy
- **Body font:** `[BODY_FONT_FAMILY]` — for body text, UI, paragraphs
- **Pairing rationale:** [PAIRING_RATIONALE]

**Step 1: Add the Google Fonts link** to your HTML `<head>` (the URL is in `tokens.json` under `typography.googleFontsUrl`):

```html
<link rel="preconnect" href="https://fonts.googleapis.com" />
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />
<link href="[GOOGLE_FONTS_URL]" rel="stylesheet" />
```

In Next.js, use `next/font/google` instead:
```tsx
import { [DISPLAY_FONT_VAR_NAME], [BODY_FONT_VAR_NAME] } from 'next/font/google';
```

**Step 2: Reference via tokens** — never hardcode the font names in component code:

```css
h1, h2, h3 { font-family: var(--font-display); }
body, p, button, input { font-family: var(--font-body); }
```

Or in JS:
```tsx
<h1 style={{ fontFamily: 'var(--font-display)' }}>Hello</h1>
```

**Don't substitute** the chosen fonts for "similar" alternatives. The display + body pair was chosen for this specific brand's archetype + tension. Swapping `[DISPLAY_FONT_FAMILY]` for, say, Playfair "because it's also a serif" breaks the pairing's intent.

**If the user wants to change the typography:** rerun `/design-system` from the typography step, or have the user explicitly request alternative pairings ("show me 3 other display options"). Don't quietly swap.

## 4. Component Patterns

Compose all primitives from tokens. Never introduce new colors, fonts, or radii.

**Button (primary):**
```css
padding: var(--space-3) var(--space-5);
background: var(--color-brand);
color: var(--color-neutral-50);
border: none;
border-radius: var(--radius-md);
font-family: var(--font-body);
font-weight: 600;
font-size: 0.9rem;
transition: background 160ms ease;
```

**Button (secondary):**
```css
padding: var(--space-3) var(--space-5);
background: transparent;
color: var(--color-brand);
border: 1px solid var(--color-neutral-300);
border-radius: var(--radius-md);
```

**Card:**
```css
background: var(--color-surface-card);
padding: var(--space-5);
border-radius: var(--radius-lg);
box-shadow: var(--shadow-md);
border: 1px solid var(--color-neutral-200);
```

**Input:**
```css
padding: var(--space-3) var(--space-4);
background: var(--color-surface-card);
color: var(--color-neutral-900);
border: 1px solid var(--color-neutral-300);
border-radius: var(--radius-sm);
font-family: var(--font-body);
/* :focus */ border-color: var(--color-brand); outline: 2px solid var(--color-brand); outline-offset: -1px;
```

**Nav:**
```css
font-family: var(--font-body);
font-weight: 500;
color: var(--color-neutral-700);
/* active */ color: var(--color-brand);
gap: var(--space-5);
```

When in doubt: look at the Applied tab of `showcase.html` — it renders these patterns using this system's specific tokens.

## 5. Tension & Voice

**Declared tension:** "[TENSION]"

- The **lead side ("[LEAD_SIDE]")** is where the system gets louder. Amplify it in:
  - Hero headlines (display font at max scale)
  - Primary CTA buttons (brand color, confident copy)
  - Accent highlights (callouts, badges, "new" markers)
  - Marketing surfaces (landing pages, onboarding)

- The **quiet side ("[QUIET_SIDE]")** is the restraint. Keep it in:
  - Body UI (forms, dashboards, settings)
  - Secondary actions (cancel, back, dismiss)
  - Spacing (prefer generous over tight)
  - Daily-use screens where noise becomes fatigue

**When in conflict:** the lead side wins in marketing moments; the quiet side wins in daily-use surfaces. Respect both. Neither alone defines the voice.

## Maintaining This System

- **Palette changes:** edit `tokens.json`, regenerate `tokens.css`, re-check contrast.
- **New icons:** generate new SVG matching existing set (see Section 2), add to `design/icons/`.
- **Font extension:** follow `glyph-spec.md`, save new glyphs to `design/fonts/`.
- **Showcase refresh:** if the brand name, tension, or archetype changes materially, regenerate `design/showcase.html`.

To regenerate the whole system from scratch, run `/design-system` again in this project root.
