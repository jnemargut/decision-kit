Decision 3 of 6 · /design-system

How does /design-system stop converging?

The workshop skill collects four rich signals — archetype, adjective sliders, reference DNA, signature tension — then launders them through a static archetype→font lookup table and a fixed showcase skeleton. The result: different inputs, weirdly similar outputs. Where does the upgrade's center of gravity go?

Builds on Decisions 1–2: banned defaults are now kit policy, and /visual-design is getting unique voices per tradition + CSS-only composition signatures. This decision is about the workshop skill's distinct failure mode.
Research Context
  • The "shadcn default" effect is the named problem for design systems specifically. AI tools treat the most statistically likely system (shadcn/Tailwind defaults, indigo gradients, rounded corners) as the answer; "AI tools that skipped the customization step made apps ugly." The customization step is exactly what this skill sells. Bhuwan Garbuja, AXE-WEB, Built In
  • Traceability is the test of a real identity system. Brand-design practice: "if a brand can't connect its visual decisions back to its archetype, the archetype isn't real." Every generated choice should be traceable to a workshop signal — that's an enforceable rule, not just a value. Marlo Studios, brand archetype guides
  • "Dominant colors with sharp accents outperform timid, evenly-distributed palettes." The current palette formula distributes semantic colors evenly — the timid pattern Anthropic's guidance warns against by name. Claude frontend-aesthetics cookbook
  • Audit: the archetype table converges on the banned font. Inter appears in the type tendencies of Creator, Sage, Ruler, and Everyman — 4 of 12 archetypes share a body voice, and Fraunces/Playfair dominate display. The pool from Decision 2's research (Bricolage Grotesque, Space Grotesk, Plus Jakarta, Fontshare faces) barely appears.
  • Audit: the deliverable itself is a template. Phase 6's showcase uses a "Fixed Skeleton" by design — every run produces the same tabs, same hero-card-form-nav Applied sections. A Jester system and a Ruler system ship in identical wrappers.
  • Audit: the signals are collected but under-spent. Sliders only nudge saturation/scale; tension only moves "pop locations"; reference DNA falls back to recall when fetch fails. The skill's four discovery steps are its moat — and they currently buy very little variance.
Options
A

Widen the pools + ban defaults

Expand each archetype's type tendencies from ~4 to 12+ pairings drawn from the 2026 characterful pool, rewrite palette logic to "dominant + sharp accent," forbid Inter/Roboto/system as display or default body.

1Workshop (unchanged)
2Archetype font table ×3 deeper expanded
3Palette: dominant + sharp accent rewritten
4Generation obeys ban list new

Direct analog of Decision 1 — cheap, safe, clean diff

Kills the worst offenders (Inter ×4 archetypes) immediately

A wider table the model still samples familiarly from — convergence happens at selection time, not just pool size

Showcase template sameness untouched

★ Recommended
B

Make the signals bite (amplification rules)

Keep the workshop, change what it buys: every output choice must trace to a named signal; slider extremes force non-obvious picks; the tension must produce at least one visible rule-breaking move; reference DNA can override the archetype table. Ban list + pool widening folded in as supporting data.

1Workshop (unchanged UX)
2Signal→choice traceability required new rule
3Tension ⇒ one rule-breaking move new rule
4Wider pools + ban list folded in
5Rationale printed per choice in showcase new

Attacks this skill's actual failure mode — signal compression to the generic middle

Subsumes A: bans + wider pools become the data layer under the rules

Traceability makes outputs defensible ("Outlaw + 'warm but feral' → this palette")

Rule-writing is subtle — over-constrain and outputs get gimmicky

Showcase wrapper still fixed unless C is layered on

C

Art-direct the deliverable

Vary the showcase itself: per-archetype layout, copy voice, and motion for the showcase and Applied tab, reusing Decision 2's composition-signature machinery. The wrapper finally matches the system inside it.

1Workshop + generation (unchanged)
2Showcase skeleton per archetype 12 variants
3Applied tab gets composition guidance new

Biggest visible wow — the artifact users actually share stops being a template

Reuses /visual-design composition work — good sequencing economics

Cosmetic if tokens underneath still converge — paint on the same fonts

12 skeleton variants is real maintenance surface

D

Live-trend curation engine

Replace the static lookup entirely: each run fires web research for current font/palette movements matching the archetype + tension, and curates from live data — the calibration pattern promoted to the core mechanism.

1Workshop (unchanged)
2Web research per run new core
3Curate from live trend data new
4Static table kept as offline fallback demoted

Never ages; maximum cross-run variety

Strong story for the repo ("library that never goes stale")

Run quality hostage to search quality; slower, flakier

Offline/headless runs degrade to the old behavior
